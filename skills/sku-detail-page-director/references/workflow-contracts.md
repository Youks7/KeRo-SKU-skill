# 工作流与输出契约

按当前阶段只读取对应部分。字段是交付下限，不是让用户填写的表格。

## 阶段一：产品判断

**目标：** 建立事实账本，选择产品处理模式，找到非模板化切入点。此阶段不输出正式 Prompt。

默认简版输出按以下顺序：

1. **我看到了什么**：产品类型、形态、颜色、可见表面、包装/组件、图片可用性；只说可见内容。
2. **推荐模式**：A/B/C、理由、风险和操作后果。
3. **事实边界**：已确认事实、谨慎推断、不能写入卖点的信息。
4. **购买机会**：目标用户、购买动机、主要顾虑和详情页优先解决的问题；均标为推断，除非用户确认。
5. **同质化扫描**：本类目常见构图、背景、道具、色彩或文案套路；指出本 SKU 要避开的具体元素。
6. **三个视觉记忆点**：每项写“来自何处—为什么专属—最适合哪类画面”。
7. **默认推进与唯一决策**：列出平台、语言、屏数、未确认卖点等假设；只请用户回复“继续看方向”或补充最影响结果的信息。

完整模式可补充产品气质、适用场景与不适合的视觉方向，但不能为了“完整”制造事实。

## 阶段二：方向提案

**目标：** 给用户三个可真实选择的策略，未经确认不输出正式 Prompt。

每个方向都要包括：

- 名称和一句销售论点（可用功能转化、场景种草、高端质感等命名，但不能只换形容词）。
- 适合平台与人群、核心购买动机、风险。
- 首屏钩子、页面节奏、主要视觉记忆点与必须避开的模板元素。
- 5–8 屏的“屏幕任务 → 未来画面”缩略图清单，不写正式 Prompt。
- 适合度（高/中/低）和判断理由。

三个方向必须组成下列差异矩阵；如某项相同，解释为什么仍能清楚区分：

| 维度 | 方向 A | 方向 B | 方向 C |
| --- | --- | --- | --- |
| 销售论点 |  |  |  |
| 首屏构图 |  |  |  |
| 背景/空间语言 |  |  |  |
| 镜头与光线 |  |  |  |
| 情绪钩子 |  |  |  |
| 专属视觉记忆点 |  |  |  |

结尾给出一个明确推荐和一个低摩擦决策，例如“回复 A / B / C、A+B，或‘按推荐方向’”。

## 阶段三：逐屏生产

**前提：** 用户已选方向，或明确说“按你推荐的来”。只制作该方向。

先给一个不超过 8 行的制作总览：已确认方向、平台/比例、屏数、模式、统一色彩/光线/排版原则、仍待确认信息。

然后每屏使用以下契约：

```text
### 屏幕 {编号}｜{屏幕任务}
销售任务：
画面与构图：
产品处理：A / B / C；产品位置或合成预留区：
文字后期：主标题方向；文字安全区；不让模型生成文字。
镜头矩阵：距离｜角度｜产品状态｜背景｜光线｜道具｜与上一屏差异。
专属细节：至少两个来自已确认产品事实或已标注推断。
Prompt：按模式输出（英文优先，除非用户指定模型或语言）。
Negative Prompt：按需缩减，不机械堆词。
质检：产品身份｜事实边界｜本屏差异｜平台适配。
```

- 用户没要求整套时，优先完成前 3 屏并请求确认视觉系统；用户要求“完整详情页”时才一次完成全部。
- 模式 A 的 Prompt 只写背景、场景、光影、道具、构图、产品预留区和文字安全区，禁止描述产品本体。
- 模式 B 的 Prompt 首句说明上传产品图是唯一参考，并明确要保持颜色、结构、Logo、包装文字和关键外观。
- 模式 C 在总览和每个 Prompt 块明显标注概念用途限制。

## 首屏 A/B 测试

只在用户要求首屏优化、测试或竞争激烈时使用。输出 2–3 个首屏，不是把同一画面换色：

| 版本 | 1 秒内传达 | 构图与情绪 | 测试假设 | 风险 |
| --- | --- | --- | --- | --- |
| A | 产品是什么、主要利益 |  |  |  |
| B |  |  |  |  |
| C（可选） |  |  |  |  |

每个版本在后续需要时再按“阶段三”屏幕契约给出 Prompt。

## 项目状态

每次回复末尾用下面格式续接，不重复完整方案：

```text
【项目状态】
阶段：1 / 2 / 3
已确认：{仅事实与用户决策}
谨慎推断：{不超过 3 条}
模式：A / B / C（理由）
方向：{未选 / A / B / C / 混合}
默认假设与缺口：{不超过 3 条}
下一步唯一决策：{用户可直接回复的话}
```

发送前自检：阶段一是否没有 Prompt；阶段二是否没有正式 Prompt 且三方向有真实差异；阶段三是否只做已确认方向、每屏均有模式和质检。
